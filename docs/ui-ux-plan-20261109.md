## 目的

OpenHinoVoiceの録音、処理、入力結果を、好みの音と表示で分かるようにする。使い始めの迷いと操作の邪魔を減らし、現在の軽量な常駐構成を保つ。
この文書は2026-11-09時点の実装計画である。プリセット、ロゴ、音、プレビューは未作成で、完成した見た目や性能改善を示すものではない。
Experience Firstに従い、保存前プレビューと状態の理解を優先する。Sequence work into verifiable unitsに従い、安全な音再生、設定、資産、プレビューを検証できるコミットへ分け、壊れた中間状態を残さない。Laziness Protocolに従い、既存のDraft、Win32、eguiを使う。

## 目標

- 音とHUDの組合せを選ぶ5つのプリセットを用意する。仮称は標準、ソフト、ミニマル、サイレント、リッチとし、音と表示を別々にも選べるようにする。
- 個別調整、保存、保存した状態へ戻す、明示的な「試す」を実装する。個別値がプリセットと一致しなければ「カスタム」と表示する。
- 独自ロゴ3案を16pxで比較し、採用案1つからSVG原本、9サイズ入りICO、トレイ明暗・状態差分、設定画面用アイコンを作る。
- 音の再生バッファとキャッシュを有界にし、無音設定で録音の先頭を捨てない。1回の出力結果に対して結果音は1つにする。
- 控えめな演出から華やかな演出まで選べる状態遷移、動きを減らす設定、DPI、キーボード、エラー表示を実装し、実画面の確認結果と性能差を残す。
- 成果をsrc/settings.rs、src/settings/preview.rs、src/feedback.rs、src/config.rs、src/sound.rs、src/overlay.rs、src/app.rs、assets/branding、assets/soundsへ置く。新規モジュールの登録は統合担当が行う。
- 比較・検証はreports/qa/ui-ux-20261109とreports/perf/ui-ux-20261109へ保存する。タスクごとに検証可能な小さいコミットを作る。

- プリセット選択は編集中の実値へ展開する。テーマの明暗とフィードバックのプリセットは別の設定とする。統合プリセット名は実値から導き、保存値と二重管理しない。
- 既存TOMLのsounds、volume、theme、live_caption、partial_caption、caption_positionを保持する。caption_anchorはAPI名で、現在の保存キーではない。

- 起動音は既定でオフ。サイレントは音を無効にするプリセットであり、エラー・録音状態の表示まで消さない。既存利用者へCancel音を自動追加しない。

5プリセットの違いは次の提案を出発点にする。図案や音源の完成を意味せず、実音量・周波数・長さは試作と評価で決める。既存設定の移行時には自動選択せず、利用者の値を保つ。

| 仮称 | 音の方向 | HUDの方向 |
|---|---|---|
| 標準 | 従来の4音を基準にする。 | 現在の標準HUDと必要な状態案内。 |
| ソフト | 角のない短い音。音量は個別調整できる。 | 控えめな動きと明瞭な状態文字。 |
| ミニマル | 開始・完了など必要な音だけ。失敗音も個別に選ぶ。 | 省スペース表示。必要な注意は省略しない。 |
| サイレント | 全イベント無音。 | 文字と形で録音・結果を伝える。 |
| リッチ | 短い和音と重なりのある音色。単に音量を大きくせず、開始・完了・注意を聞き分ける。 | 音声に連動する滑らかな波形、小さな光彩、開始の波紋、成功時の短い収束と粒の演出。 |

音セットとHUDは別々にも選べる。例えば「リッチな表示＋無音」「ミニマルな表示＋リッチな音」も保存できる。各イベントを個別に無効化でき、個別変更後は実値からカスタム判定する。起動音の既定オフと既存利用者のCancel無音を全プリセットの初期移行で守る。

リッチも最初から実装対象に含め、利用者が選んだ場合に有効にする。次は試作の仕様であり、完成した音や動きではない。Experience Firstに従い、好みの表現を選べることと入力の速さを両立させる。

| 場面 | リッチな音と動きの案 |
|---|---|
| 起動・録音開始 | 起動音を有効にした場合は短い和音とロゴの波紋。録音開始は短い音と1回の波紋で示す。Start音は現行の約163msを超えない設計とし、華やかさのために録音除外区間を延ばさない。起動音は既定オフのまま。 |
| 録音中 | 既存の音量値を使って波形を滑らかに補間し、輪郭に小さな光彩を付ける。追加のマイク取得や解析、ループ音は不要。 |
| 認識・整形中 | 状態文字と細い周回表示で処理中を伝える。完了率を捏造せず、状態が変われば前の演出を中断してすぐ切り替える。 |
| 成功 | 短い和音1つとチェックの描画、最大6個の粒が収束する演出。完了音は500ms以内、視覚演出は600ms以内を試作上限とし、入力送信後に非同期で実行する。 |
| 注意・失敗・取消 | 注意は柔らかい単音と状態アイコン、失敗は判別できる短い音と説明、取消は縮小とフェード。成功用の粒や和音は使わず、意味を混ぜない。 |

- 音の重なりや残響は制作時に単一の短いPCMへ合成する。実行時の多重再生・DSP・音響用依存は追加しない。音源間の知覚音量とピークを比較し、既存の音量調整を共通に使う。
- 光彩は小さなキャッシュ済み素材、波形と粒は上限付きの描画データを使う。演出中だけ最大60fpsを試作上限とし、余分な全画面描画や毎フレームの資源作成を避ける。停止・非表示・最小化では演出の更新を止め、再表示時は現在の状態へ復帰する。
- 録音中・処理中の状態表示に必要な動き以外は有限時間で終える。静止中の常時発光アニメーションは入れず、音と動きのために録音・入力・次の操作を待たせない。
- OSまたはアプリの「動きを減らす」が有効なら、リッチを選んでも波形・波紋・粒・拡大縮小・周回を静止表示へ置き換える。音の選択とは独立させ、注意の文字と形は保持する。

- 保存前のプレビューはPreviewStateとしてDraftから分離する。合成レベルと合成文章で設定画面内に描き、マイク、ASR、AI、履歴、グローバルキー、貼付、設定保存を実行しない。
- 画面を開く、hoverする、プリセットを選ぶだけでは鳴らさない。「試す」またはイベント別の再生ボタンだけで鳴らす。「試す」を再度押すと停止する。
- プレビュー停止、Esc、ページ離脱、設定終了で音・タイマー・描画要求を回収する。通常の録音やHUDの状態を書き換えない。
- 設定は別プロセスなので、本体状態を副作用なく確認してから試聴する。録音中は音の試聴不可、本体が録音を始めたら試聴を停止する。本体の録音を試聴のために拒否・遅延させず、状態照会後に録音が始まる競合も防ぐ。状態取得に失敗したら無音の視覚プレビューだけに限定する。重いIPCサーバーや常駐pollを足さない。
- U05bの有力な提案は、試聴の再生所有を本体へ寄せ、設定から既存Win32メッセージ経路で小さな再生・停止要求だけを渡す方式である。同じ本体loopが録音開始前に試聴を止め、単発照会のTOCTOUを避ける。これは未実装の設計案で、既存HWNDの発見とメッセージ適用可能性を小さいprototypeで確認して確定する。
- 要求はPlay(id, volume, token)とStop(token)を候補にする。再生所有者とpreview世代tokenを本体が保持し、録音開始時はpreview tokenを無効化して旧音を停止してから本番Startへ進む。遅れて届くStop・期限・closeは同じpreview所有時だけ作用し、本番Start・Done・Errorや再生中PCMを止めたり解放したりしない。
- IPCの候補はWM_COPYDATA等の小さな値メッセージと、待ち時間を限定したSendMessageTimeoutである。許可enum・音ID・音量・token・長さを受信callback内で検証して所有バッファへコピーし、適用時にも世代と本体状態を照合する。ペイロードに別プロセスのポインタを含めない。送受信HWND、PID、sandbox名、timeoutを小試作で検証し、方式を確定する。[Data Copy](https://learn.microsoft.com/en-us/windows/win32/dataxchg/data-copy)、[WM_COPYDATAの寿命規則](https://learn.microsoft.com/en-us/windows/win32/dataxchg/wm-copydata)、[SendMessageTimeout](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessagetimeoutw)
- 任意ファイルや任意コマンドを渡さない。期限到来と設定closeで同じpreview世代だけを停止する。本体不在・応答不明なら無音の視覚previewへ戻す。新server・thread・常駐pollは加えない。これらは未実装の設計候補である。
- 共有mutexだけで試聴と録音を排他にする案は、試聴中に本体録音を拒否するため採用しない。
- 視覚プレビューは本番と同じ状態・描画規則を使う。GDIのoffscreen描画をeguiへ渡す方式も候補に、U05bで最小adapterを決める。描画の二重実装や常駐GPUを前提にしない。
- ユーザーの作業を妨げるターミナルや前面ウィンドウを出さない。コマンドはNodeのchild_processからwindowsHide:true、shell:falseで直接実行する。PowerShellを使う場合も非表示のpwsh.exeへ-Fileで渡す。
- 実機UI確認は隔離した設定と明示したプレビュー入口で行う。フォーカスを奪わない方法で確認できなければ、その実画面項目を未確認として残す。通常テストを実画面確認の代わりにしない。
- 既存の未コミット変更、ユーザーの設定・認証情報・導入済みアプリを保持する。push、公開、インストールはこの計画のコミット単位に含めない。

イベントごとの意味を次のように揃える。sound_eventsは各イベントの有効・無効を保持し、音セットの音源と分離する。

| イベント | 意味と既定 | 表示との対応 |
|---|---|---|
| Startup | 起動できた通知。既定オフ。新規の長いジングルは不要。 | 起動だけで録音や認識準備が完了したとは表示しない。 |
| Start | 録音が開始した。既存設定を維持。 | 準備中でも録音していることを示す。音の初期化を待って録音を遅らせない。 |
| Stop | 録音を終え、認識を待つ。既存設定を維持。 | 完了と区別する。Enter後に音声が録音済みであることを示す。 |
| Done | 入力を送信した成功。既存設定を維持。 | 入力先本文を確認したという意味にはしない。 |
| Doneの注意付き結果 | 原文への一部復帰や履歴保存失敗を伴う入力送信。 | 短い注意音1つと注意表示を選ぶ。Doneの直後にErrorを重ねない。 |
| Error | 入力できない、録音できないなどの失敗。既存設定を維持。 | 回収先や再試行先を表示する。色だけで失敗を伝えない。 |
| Cancel | 利用者が録音や処理を取り消した。現状未実装なので既存設定では無音。 | 失敗とは区別し、取り消した状態を短く伝える。 |

## 注意事項

- sound.rsはSND_ASYNCでWAVメモリを再生する。再生所有者と世代にPCMの寿命を結び、停止・完了を確定してから解放する。古いpreviewの停止要求が、所有者の変わった本番音や新しいPCMを解放してはいけない。
- 現行キャッシュはBox::leakで解放しない。現状の4音と1〜100の音量だけなら400組で有界だが、全音量を使うと原音合計の100倍、7,158,000 bytesを保持する。音セットの追加前にこの方式を置き換える。
- app.rsの開始音除外はsounds=trueだけを見ている。volume=0でも約203msを捨てるため修正する。録音開始前にpreviewだけでなく前世代のDone・Startup等も停止・無効化する。先頭除外は、そのセッションで再生開始に成功したStart音源の長さを基準にする。出力遅延の補正は実測で見直し、根拠なく削らない。Start無効・volume=0・再生なしなら0とし、無音時の固定203msや40msを残さない。
- app.rs:930付近はDone音の後に履歴保存失敗や原文復帰のError音が鳴り得る。成功・注意付き成功・失敗を先に1つ選び、表示と音に同じ結果を渡す。
- 保存済み設定、編集中設定、プレビュー状態を混ぜない。「戻す」は音と表示の編集中項目だけを保存値へ戻し、APIキーや他ページの変更を消さない。
- モデル取得のJob管理、設定終了の非同期待機、クリップボード復元、履歴回収をUIの整理で崩さない。src/settings/setup.rsのプロセス制御は初回状態表示のために作り直さない。
- 演出は準備・録音・認識・整形・成功・注意・取消・失敗を読み取れる状態遷移とする。リッチでは光彩・波紋・粒も選べるが、演出だけの待機時間や無限の装飾アニメーションは入れない。既存の140ms入場、200ms退場、文字・GDI資源の再利用を出発点とする。動きを減らす設定では波形・点滅・移動を抑え、状態名と必要な音量表示を残す。
- icon追加時はbuild.rsのrerun入力にその資産を足す。reports全体の監視へ戻さない。トレイHICONの交換と破棄、DPI変更時の再生成を同じ所有規則で扱う。
- ICOの9サイズはWindowsのDPI別表示を考慮した本計画の選択である。各サイズで線を調整し、16pxの判別性を先に確認する。[Microsoftのアイコン設計指針](https://learn.microsoft.com/en-us/windows/apps/design/iconography/app-icons)、[サイズと構成](https://learn.microsoft.com/en-us/windows/apps/design/iconography/app-icon-construction)
- Cargoの共有target、常駐プロセス、実機オーディオ、GPUは共有資源である。UI性能測定とASR診断を同時に走らせない。Cargoのロック待ちを異常として停止しない。
- 既存の動画向けPNG38枚・JPG26枚は現在のUIスクリーンショットではない。動画用raw効果音35WAVも本番の4WAVと区別する。見た目の証拠には、新しい条件付きキャプチャを使う。

## イレギュラー対処

- 音デバイスがない、初期化が遅い、再生が失敗した場合は録音と入力を続ける。結果音を失敗音でさらに上書きせず、必要なら設定画面に音の利用不可を示す。
- 未知のプリセット値や旧TOMLでは従来の個別値を優先する。破損した新項目だけ既定値で扱い、警告と保存前の差分を確認できるようにする。
- 高コントラストや動きの無効化では専用の簡素表示へ切り替える。Windows設定変更後も再起動なしで更新する。API取得失敗時は設定画面の明示値を使用する。
- HUDのキャレット位置を取得できない場合は既存の画面上端へ戻す。長文・小さい画面では省略と全文の確認手段を設け、操作ボタンを画面外へ追い出さない。
- 見た目の案が同点なら16pxの識別性、明暗背景、既存の赤との相性で選び、比較画像と理由を残す。OpenHinoVoiceという名前に未確認の由来を付けない。
- 資産生成に失敗しても音の所有権修正、互換設定、状態試験を進める。未取得資産はプレースホルダーと明記し、正式アイコン完成とは扱わない。
- Fastが0件、fixture不実行、測定対象のハッシュ不一致なら成功記録を作らず修正する。実機確認ができない項目は未確認一覧へ残す。

## 緊急停止

- プレビューが本物の録音・外部通信・貼付・ユーザー設定の書換えを起動したら、そのプレビューを直ちに止める。隔離データとログを保持し、副作用の入口を修正する。
- 音が停止しない、メモリやGDIハンドルが切替ごとに増え続ける、OOMが起きる場合は自分のプレビューだけを停止する。導入済みアプリや他担当のプロセスを一括終了しない。
- 操作処理が1秒以上UIを止める、またはUIを操作不能にする場合は演出を無効化して原因を調べる。音源のロードや変換を同期入力処理へ戻さない。
- 復旧可能な文章が失われる、保存・貼付の既存回帰が失敗する場合は統合を止める。直前の小さい変更単位で修正し、既存のユーザーデータを削除しない。
- buildが遅いだけ、試験用機器がないだけ、ロゴが未決定なだけでは全作業を止めない。依存しないタスクを継続し、成果物の検証範囲を明記する。

## 時間

UI実装とASR診断の作業量の目安は延べ25〜38時間。既存依存が取得済みで、最大3担当が所有範囲を分けて動く前提なら、待ちを除く実作業は2〜4日程度を見込む。リッチな音とアニメーションの試作3〜5時間を含む。これは新音・図案の初稿、修正1回、通常回帰、UI確認1巡の見積りで、実機差や再設計は含まない。

ASR診断後の小さい改善U13には追加3〜6時間を仮置きする。診断で変更対象が確定した時点で見積りを更新し、UIの完了待ちに隠さない。
既存観測ではrelease build約8.6分、キャッシュ利用のFast約15.9秒だった。初回compileや新資産後のlink時間を保証する値ではない。関連テストを先に行い、Fullは統合した区切りでまとめる。
各担当は次の入力と完了条件を持って自律的に進める。親は共有target、実画面、音デバイス、性能測定の予約だけを直列化する。受入不成立は証拠付きで修正し、成果物の種類が変わらない判断を毎回ユーザーへ戻さない。
