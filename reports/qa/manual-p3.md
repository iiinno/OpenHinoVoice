# 手動確認: P3(ローカル LLM、オフラインモード)

実機と利用者の操作が必要な確認。完了条件は「Wi-Fi を切った PC で、
OpenAI 互換の API を持つローカルのエンジンを接続先にして、録音から
整形済みの貼り付けまでが動くこと。確認には、性質の違う 2 種類以上の
エンジンを使う」。

## 確認 1: ローカル LLM との接続(2 種類以上)

1. 性質の違う 2 つのローカルエンジンを用意する(例: llama.cpp 系の
   サーバー 1 つ、別の実装 1 つ。どちらも OpenAI 互換の API を持つこと)
2. 設定の「整形(AI)」で接続先「この PC の LLM」を選び、URL に
   `http://127.0.0.1:8080/v1` の形で入れる
3. 「一覧を取得」でモデルの一覧が出ることを確かめる(出ないエンジンでは
   モデル名を手で入れる)
4. 「接続テスト」を通して録音 → Enter → 整形済みの貼り付けまで試す

期待する結果: 2 つのエンジンとも、録音から整形済みの貼り付けまで動く。
録音を始めてからすぐ Enter を押しても(モデルの読み込みが間に合わなくて
も)、整形が失敗しない、または時間がかかっても最後まで通る。

## 確認 2: オフラインモード

1. 設定の「整形(AI)」でオフラインモードをオンにする
2. Wi-Fi(と有線)を切る
3. 接続先をローカルのエンジンにして録音 → Enter → 貼り付け
4. 接続先をクラウド(OpenCode Go など)に変えて録音 → Enter

期待する結果: 3 は最後まで動く。4 は整形が行われず、生テキストが
貼られて「生テキストを貼りました(オフラインモードでは…)」という
理由の表示が出る。

## 確認 3: 認識モデルが未取得のときの案内

1. オフラインモードをオンにしたまま、認識モデルのフォルダから
   Haas のモデルを一時的に退かす(もとに必ず戻すこと)
2. openhinovoice.exe を起動する

期待する結果: 起動時に「認識モデルが未取得です。オンラインのときに
1 回取得してください」という表示が数秒出る。モデルのダウンロードは
始まらない。確認後はモデルをもとに戻す。

## 確認 4: extra_body の編集

1. 「リクエストの追加項目(extra_body)」に
   `{"reasoning_effort": "minimal"}` のような JSON を入れて保存する
2. 設定ファイル(config.toml)を開き、extra_body に反映されていること、
   他の項目のコメントが消えていないことを目で確かめる
3. 不正な JSON(`{` だけなど)を入れて保存しようとする

期待する結果: 2 の内容が保存され、3 は「JSON が不正です」という
理由の表示で保存できない。
