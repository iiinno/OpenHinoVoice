# 手動確認: P4(Edit モード)

実機と利用者の操作が必要な確認。完了条件は次のとおり。

- メモ帳、ブラウザの入力欄、Word で、文を選んで録音開始キーを押すと Edit になり、指示どおりに置き換わる
- 文を選んでいないときは、どのアプリでもこれまでどおりの音声入力になる
- UI Automation で選択を読めないアプリでは「このアプリでは Edit を使えません」と出て、通常の音声入力になる
- Edit をオフにすると、選択の確認そのものを行わない
- 選択の確認でキー操作を送らず、クリップボードにも触れない

## 確認 0: 対応表を作る(uia_probe)

1. `cargo run --release --example uia_probe` を実行する
2. 次のアプリをそれぞれ前面にして文を選ぶ。プローブの表示を記録する
   メモ帳 / Word / Edge と Chrome の入力欄 / VS Code / Slack / Teams /
   Windows Terminal
3. 結果を README.md の「Edit を使えるアプリの対応表」に書き込む
4. あわせて、選択していない状態の表示も確かめる(「選択なし」と出る)

## 確認 1: 置き換えができる

1. 整形(AI)の接続先を設定しておく
2. メモ帳に文を書き、その一部を選んだ状態にする
3. 録音開始キーを押す
4. 表示が「編集」になり、選んだ文の先頭が出ることを確かめる
5. 「丁寧にして」のように指示を話して Enter を押す

期待する結果: 選んだ部分が指示どおりに置き換わる。置き換えの前に
選択が残っているので、選択範囲だけが入れ替わる。

## 確認 2: 選択がないときは通常の音声入力

1. 何も選んでいない状態で録音開始キーを押し、普通に話して Enter

期待する結果: これまでどおり、話した文が入力される。Edit の表示は
出ない。

## 確認 3: 読めないアプリの扱い

1. 対応表で「対応していない」と出たアプリ(たとえば Windows Terminal)
   を前面にして、録音開始キーを押す

期待する結果: 「このアプリでは Edit を使えません」と数秒出て、
通常の音声入力として録音が始まる(表示は消えたあと、録音の表示に戻る)。

## 確認 4: 長い選択とオフのとき

1. 6000 文字を超える文を選んで録音開始キーを押す → 「選択が長すぎるため
   Edit を使えません」と出て通常の音声入力になる
2. 設定で Edit モードをオフにして、文を選んだ状態で録音開始キーを押す →
   Edit の確認は行われず、通常の音声入力になる(対応していないアプリでも
   何も表示しない)
3. 整形(AI)の接続先を空にして、文を選んで録音開始キーを押す →
   「Edit には整形(AI)の接続先が必要です」と出て通常の音声入力になる

## 確認 5: キー操作とクリップボードに触れないこと

1. クリップボードに何かをコピーしておく
2. 文を選んだ状態で録音開始キーを押し、Edit の指示で置き換える
3. 貼り付けのあと、クリップボードの履歴を開く

期待する結果: Edit の過程でコピーしたものが履歴に増えていない
(選択の読み取りにクリップボードが使われていない)。キー操作も
入力先に届いていない(メモ帳で試すと、勝手な文字入力がない)。

## 確認 6: 復旧履歴

1. Edit で置き換えたあと、設定の「履歴と再入力」を開く

期待する結果: 置き換える前の文と後の文が履歴に残っている。
