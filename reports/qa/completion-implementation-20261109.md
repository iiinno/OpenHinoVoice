# v0.5.0の仕上げと軽量化

対象は `codex/v050-finish` の作業ツリー。基準コミットは `29c80b90d47a96dddd4cb061a19cda1b88cb1db2`。必要な機能を残し、入力・保存・終了の不具合、初回設定、余分な処理、検証の入口を変更した。

準備完了通知の競合、準備中の案内、不要な再ビルド、非同期writerのテスト待機を含む最終ソースのFull、キャッシュ確認、最終exeの待機計測は合格。未実施の実機試験を成功として扱わない。

## 実装したこと

| 領域 | 変更と利用者への効果 |
|---|---|
| キー入力 | 専用のメッセージ処理を持たせ、履歴保存や描画の待ちに巻き込まれないようにした。押しっぱなしのEnter、キーの押下・解放、開始直後の操作順序を維持する。 |
| 原文回収 | 保存を担当する処理へ内容を渡し、更新番号付きで完了を受け取る。保存失敗時は原文をメモリにも保持する。回収待ちが多い場合は新しい録音を止め、古い文章を黙って捨てない。削除前に予約された保存で履歴が復活する競合も防ぐ。 |
| 貼り付け | 同じSTAでクリップボードを保持し、250ms後に復元する。その間も画面の処理を続ける。別のコピー操作を上書きしないよう更新番号を照合し、同時の貼り付けを制限する。 |
| 設定と認識 | 録音開始時の設定を固定し、実行ファイルとモデルが一致するworkerだけを再利用する。設定は同じ場所の一時ファイルから置換し、保存失敗時に既存内容を残す。 |
| 失敗の案内 | UIAの時間切れ、マイクの切り替え・録音エラー、AI整形の一部原文への復帰を区別する。案内と実際の回収先を一致させる。モデル準備中も録音を続けていること、Enter後は録音済みであることを表示し、準備完了時だけ表示を更新する。 |
| 初回設定 | モデルの取得状況・進捗・中断、10秒のマイクレベルテスト、録音→Enter確定／Esc取消の案内、未保存変更の確認を追加した。 |
| 終了 | 保存とクリップボード復元が完了するまでウィンドウを保持する。終了要求後の新たな貼り付けを止める。モデル処理は停止状態でJobへ登録してから動かし、設定を閉じる際は中断した旧処理も非同期に回収する。認識workerは後片付け用スレッドを作る前に終了を要求する。 |

## 処理を減らした箇所

- マイクのコールバック内の一時配列をなくし、容量を再利用する。処理が追いつかず入力バッファの上限に達した場合は、欠落を黙認せずエラーとして扱う。
- 送信用PCMは共有バッファと位置で管理し、区間を多数の小さな配列へ複製しない。辞書ヒントは録音単位で作る。
- AIの途中表示は最新の1件だけ保持する。最終結果・失敗・世代番号は別に保持する。
- ホームの履歴と統計は一度の読出しから作り、描画ごとの復号を止める。非同期取得の失敗と0件を区別する。
- 静止通知はフェード後の再描画を止める。文字、Canvas、GDI/DIBの資源を再利用する。
- ファイル文字起こしは区間を順に生成し、ファイル全体のf32配列と分割済み全区間を同時に持たない。元のPCM全体は引き続き保持する。
- モデル取得の出力は専用の読取スレッドを2本作らず、読める分だけ上限付きで取り出す。同じ接続先のprewarmは重複起動しない。

これらは削減した処理の説明であり、速度やメモリの改善率を示す数値ではない。軽量なWin32常駐部と別プロセスの設定画面、純粋な状態遷移は維持した。新しい依存crateは追加していない。

## 開発とAIの検証

共通ライブラリへ移し、`#[path]`による同じ単体テストの重複取込みを解消した。手順は [検証ガイド](../../docs/verification.md) にまとめた。

```powershell
pwsh -NoProfile -File scripts/verify.ps1 -Mode Fast
pwsh -NoProfile -File scripts/verify.ps1 -Mode Full
```

Fastは書式と通常テスト、Fullはさらにclippyとreleaseビルドを行う。関連する回帰をFastで確認し、担当レビューの修正を統合してからFullを実行する。CIも同じ入口を使う。APPDATA・LOCALAPPDATA・ミューテックス名を分離し、自動起動のレジストリ操作を抑止する。実行したソースのハッシュ、成否、所要時間、無視した試験、未実施の前提条件をJSONへ残す。0件のフィルターや欠損コーパスは失敗になる。コマンドは非表示で実行する。非同期送信のテスト5件は、固定時間後のログ読出しから実際の要求を観測する待機へ変更した。遅延をテスト側で意図的に作り、予約と送信完了を分けて確かめる。

追加測定で、レポートを更新しただけでも本体と統合テストが再リンクされることを確認した。build scriptの指紋にレポートのmtimeが入力として残っていたため、build.rsの監視を自身とCargo.tomlだけへ絞った。[Cargo公式の変更検知の説明](https://doc.rust-lang.org/cargo/reference/build-scripts.html#life-cycle-of-a-build-script)に沿った修正であり、LOCALAPPDATAの隔離は維持する。修正後はレポート更新を挟んでも再コンパイルが発生せず、Fastは236件成功・約15.9秒、releaseの再確認は約4.9秒で既存成果物を再利用した。[キャッシュ確認](validation-20261109/cache-check.json)。どちらも既存ビルドを利用する単発の値で、初回ビルド時間ではない。

実時間リプレイは本番のSession、区間分割、仮認識、確定優先、Enter後の処理を共有する。WAVを25ms単位で実時間に供給し、最初の仮認識、未認識PCM相当量、Enter呼出し直前からASR確定まで、CERを記録する。これは認識経路の検証であり、マイク、実画面への字幕描画、AI整形、履歴保存、対象アプリへの貼り付けを含むE2Eではない。

## 検証結果

最終ソースの [Full結果](validation-20261109/full/result.json) は、fmt・全ターゲットclippy・通常テスト236成功／0失敗・releaseビルドがすべて成功。通常実行で除外された11件には、実機・接続試験のほか、親テストから子プロセスとして実行するfixtureも含む。ソースのSHA-256は 9B387345580EB290B134763636CC0A4A38EEDD44EB1F937E522EBA3DE159430E。通常テストの実行部分は合計約5.4秒で、コンパイル時間は含まない。

exeは最終Fullの成果物。待機計測も同じexeで再確認した。

| 測定 | 今回の値 | 条件・解釈 |
|---|---|---|
| release exe | 7,781,376 bytes（7.42MiB） | 基準版7,645,696 bytesから132.5KiB増。実行ファイルが小さくなったという変更ではない。 |
| 待機中のPrivateメモリ | サンプル最大1.99MiB | 常駐本体だけ。音声認識エンジンと設定画面を含まない。 |
| 待機中のWorking Set | サンプル最大17.80MiB | 共有DLLを含む常駐ページ。 |
| 待機中のCPU | 0 CPU秒／分（観測値） | 60.04秒、58サンプル。WindowsのCPU計時粒度以下であり、CPUを一切使わないという意味ではない。 |

[ビルド情報](../perf/20261109-finish/build.json) と [待機中の計測値](../perf/20261109-finish/idle.json) を保存した。待機試験は隔離した設定で、オフライン、APIキーなし、worker保持なし、マイク未使用、履歴保存なし。他の開発作業の負荷を固定していない単発の測定であり、変更前後の速度・メモリ改善率を証明するものではない。検証専用に起動した常駐プロセスは終了済み。

実モデルの初期測定は次のとおり。いずれも毎回新規workerで開始し、OSやGPUのキャッシュを消していない。最終の準備通知・受信競合・ビルド入力の修正前のソースを固定して実行した。readyは各試行で正常に観測できている。

| 音声 | readyまで | 最初の仮認識 | Enter→ASR完了 | CER厳密／正規化後 |
|---|---:|---:|---:|---:|
| short（18.98秒） | 31.262秒 | なし | 17.136秒 | 11.11%／8.70% |
| 1min（61.06秒） | 15.728秒 | 23.108秒 | 1.420秒 | 15.67%／11.37% |
| 5min（303.12秒） | 42.646秒 | 86.262秒 | 26.108秒 | 7.05%／3.79% |

[shortの全計測値](../perf/20261109-finish/realtime-short.json)と[1minの全計測値](../perf/20261109-finish/realtime-1min.json)には入力とソースのハッシュ、音声供給の遅れ、未認識PCM量を含む。1minのspeech.exeだけを1秒間隔で52回採取したメモリは、観測最大Private 610.64MiB、Working Set 589.37MiBだった。[エンジンの記録](../perf/20261109-finish/speech-1min-memory.json)。常駐本体の約2MiBに、この認識エンジン分は含まれない。

[5minの全計測値](../perf/20261109-finish/realtime-5min.json)では、未認識PCMの最大値は1,342,720 bytes（約41.96秒分）、Enter時は997,120 bytes（約31.16秒分）。待ち行列は途中で減り、末尾で再び増えた。単調な増大は見られないが、終了待ち26.108秒は残る。Plan.mdのP1/P2にある「録音の長さによらずEnter後の待ちがほぼ一定」「仮認識の素早い更新」の達成は確認できておらず、30分連続録音も未実施。完成・最速という判定はしない。[測定集約と条件](../perf/20261109-finish/asr-summary.json)に記録した。

同じモデルを直接workerとして診断すると、通常起動はready 2.141秒、初回要求2.671秒、起動から初回完了4.828秒だった。warmupを省いた単発診断ではそれぞれ23.797秒、4.390秒、28.203秒となり、省略による優位は確認できなかった。[公式worker仕様](https://github.com/nyosegawa/speech.cpp/blob/v0.10.1/docs/worker.md)ではreadyはモデル読込みと通常のwarmupの後に出る。今回のstderrにはその内訳がなく、キャッシュ・初期化・他の負荷の影響を分離できていない。起動フラグと既定のworker保持時間0は変更しない。直接診断はshort全文を1要求で渡したもので、本番の区間処理の速度比較ではない。[通常起動](../perf/20261109-finish/worker-diagnostic-default.json)、[warmup省略](../perf/20261109-finish/worker-diagnostic-no-warmup.json)の証拠を保存した。

設定画面と新しい準備中オーバーレイの操作・見た目は、作業中の利用者の画面やフォーカスを動かさない指定に合わせ、今回は実機未確認として残す。モデル取得の中断・終了、未保存確認などの制御は通常テストで確認した。

独立レビューで、履歴削除後の初回保存、クリップボード取得時の更新競合、終了時の保存待ち迂回、回収用ウィンドウの早期破棄、モデル処理の子孫回収を修正した。追加レビューでは、ready前の終端受信が同じキューのready行を捨てる競合を修正し、progress→readyの順で到着する場合を録音中・認識中の両方で試験する。外部Grok経由の実行は、ターミナル表示を避ける指定に合わせて中断した。独立レビューはnativeの担当で実施したもので、外部モデルによるcross-judge完了とは扱わない。

## 残る確認と限界

- 実マイクの切断、対象アプリ本文への入力とクリップボード復元、UIAのアプリ別対応、DPI・複数モニター、実クラウドAPI・複数ローカルLLMは別途実機確認が必要。
- AI通信の途中キャンセルは、古い結果の適用を防ぐ。進行中のブロッキング読出しを直ちに中断する仕組みまでは今回変更していない。90秒も厳密な実時間の終了保証ではなく、画面の説明を合わせた。
- 実時間リプレイのbacklogは未認識音声の量であり、プロセスの実メモリ量ではない。変更前後の認識性能を同条件で多数回比較した結果がない限り、改善率やp95を主張しない。

適用した原則はLaziness Protocol、Experience First、Explain the Number、Prove It Works。既存構成を活かした境界の整理、入力と回収の信頼性、測定範囲の明示、失敗条件の回帰試験に反映した。既存の未コミットファイルを保持し、利用者の設定・認証情報・導入済みの常駐アプリは検証用に変更していない。
